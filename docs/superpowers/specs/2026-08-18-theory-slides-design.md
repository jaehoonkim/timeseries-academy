# 모듈별 이론 강의 슬라이드 (slides.md) 설계

2026-08-18. 워크시트 시작 전에 그날의 이론을 강의로 먼저 가르치는
슬라이드를 모듈 표준 구성에 추가한다.

## 배경과 결정

- 기존 수업 설계는 "손으로 겪고 → 개념 이름 붙이기"의 발견 학습
  구조였고, 시각 자료는 teacher.md의 즉석 판서 지시에 의존했다.
- 결정: 수업 구조를 "이론 강의(슬라이드) → 활동지"로 바꾼다.
  워크시트 안의 이론 설명은 그대로 두어 복습·리마인드 역할을 한다.
- 형식: Marp 마크다운. 레포의 기존 관리 방식(전부 마크다운,
  git diff 가능)과 일치하고, 필요할 때 PPTX/PDF로 내보낸다.

## 파일 구조

- 각 모듈 폴더에 `slides.md` 1개 추가 — 모듈 표준 구성이
  4개 파일(teacher, worksheet, practice, answers)에서 5개가 된다.
- 렌더링: `npx @marp-team/marp-cli slides.md --pptx` (또는
  `--pdf`). 생성된 바이너리는 커밋하지 않는다 (.gitignore에
  `*.pptx`, `*.pdf` 추가).
- 테마: Marp 내장 테마 + front-matter 설정만 사용. 커스텀 테마
  CSS는 만들지 않는다 — 필요해지면 그때 추가한다.

## 덱 분량과 내용

모듈당 12–18장, 강의 15–20분 분량. 내용은 기존 `teacher.md`(설명
대본, 판서 지시)와 `worksheet.md`(개념 설명)에서 추출·재구성한다.
새 이론을 발명하지 않는다.

구성 순서:

1. 지난 모듈 연결 1장
2. 오늘의 목표/지도 1장
3. 그날의 이론 전체 — 개념 정의, 용어, 계산 방법, teacher.md에서
   "칠판에 그리라"던 도식들
4. 마지막 장: "이제 활동지로" 전환

## 스포일러 규칙

슬라이드는 **개념과 방법까지만** 가르친다. 워크시트 질문의
**답 — 구체 수치, 해석 결론 — 은 싣지 않는다.**

- 예: "이동평균이 무엇이고 어떻게 계산하는가"는 슬라이드에서
  가르친다. 워크시트 표의 빈칸 값이나 "그래서 이 주는 오르는
  중이다" 같은 결론은 학생이 활동지에서 직접 얻는다.
- 판단 기준: 그 내용이 worksheet의 Q번호 답이면 슬라이드 금지,
  Q를 풀기 위한 도구(정의·기호·읽는 법·계산 절차)면 슬라이드 허용.

## 그래프 이미지

- 기온 그래프가 꼭 필요한 슬라이드만 모듈 폴더의 `img/`에 PNG를
  생성해 커밋한다. 생성 스크립트(matplotlib,
  `data/seoul-temp-daily.csv` 입력)도 함께 커밋해 재생성 가능하게
  한다.
- 텍스트·마크다운 표로 충분한 슬라이드는 이미지 없이 간다.

## 범위와 순서

1. 중등 M1–M8 8개 모듈 (우선) — 완료 (2026-08-18)
2. 고등 H1–H3 (기제작 모듈)
3. 고등 H4–H8은 모듈 제작 시 slides.md를 표준 구성으로 포함

슬라이드 작성 시점 (중등 제작 후 추가된 원칙, 2026-08-18): 이후
과정의 slides.md는 모듈의 다른 파일과 동시에 만들지 않고, 강의자가
워크시트·practice로 과정을 한 번 다 진행한 **후에** 마지막으로
만든다. 직접 풀어봐야 슬라이드의 오류가 보이고, 실제로 막힌 지점과
필요한 설명을 더 적절하게 넣을 수 있기 때문이다. 즉 H4–H8의 모듈
제작 시 slides.md는 "표준 구성에 포함하되, 작성 순서는 맨 마지막
(강의자 소화 완료 후)"이다.

문서 갱신: 중등/고등 README의 "파일 구성" 표(4개 → 5개)와
진행 방법, 루트 README 필요 시.

## 검증

- 각 slides.md는 marp CLI로 에러 없이 렌더링되어야 한다.
- 스포일러 규칙 준수: 완성 후 answers.md와 대조해 워크시트 답이
  슬라이드에 없는지 확인한다.
