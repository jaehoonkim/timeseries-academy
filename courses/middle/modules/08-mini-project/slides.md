## 오늘의 목표

- 각 단계에서 어떤 도구(M1–M7)를 쓸지 스스로 연결할 수 있다.

---

## 프로젝트의 다섯 단계

> 질문 → 수집 → 분석 → 예측 → 발표

- 지난 일곱 시간은 이 다섯 단계를 서울 기온 데이터 하나로,
  선생님이 정한 순서대로 연습한 것이었다.
- 오늘부터는 데이터도, 질문도, 순서를 밟는 것도 각자(또는 팀)의
  몫이다.

---

## 1단계 — 질문 정하기

좋은 시계열 질문의 세 가지 조건:

1. **시간에 따라 변하는 숫자**인가? (날짜 + 값으로 적을 수 있어야
   한다)
2. 데이터를 **구할 수 있는가**?
3. 내가 **정말 궁금한가**? (발표까지 끌고 갈 연료다)

질문 예시: "내 걸음 수에는 요일 패턴이 있을까?", "우리 동네
미세먼지는 언제 나쁠까?"

---

## 2단계 — 데이터 고르는 기준

- **날짜 열 + 값 열**로 정리할 수 있는 CSV여야 한다.
- **60행 이상** 권장 — 너무 짧으면 패턴을 볼 수 없다.
- **기간 최소 조건(M4)** — 패턴은 두 번 반복되어야 패턴이다.
  - 요일 패턴이 궁금하면 최소 2–4주.
  - 계절(연) 패턴이 궁금하면 2년 이상.
- 조건에 안 맞으면 질문을 데이터에 맞게 줄인다("연 패턴" → "요일
  패턴").

## 3단계 — 데이터 준비 (Colab)

```python
import pandas as pd

df = pd.read_csv("내파일.csv", parse_dates=["날짜열"], index_col="날짜열")
df.head()
```

- CSV의 한글이 깨지면 `encoding="cp949"`를 추가한다(공공데이터에
  흔하다).
- 그래프의 한글이 □로 나오면 먼저
  `!pip install -q koreanize-matplotlib` → `import koreanize_matplotlib`
  (워크북 2절의 준비 셀).
- 날짜 형식이 안 읽히면 `pd.to_datetime(..., format="...")`으로
  형식을 지정한다.
- 첫 점검은 늘 세 가지: 행 수, 기간, 결측 개수(M7).

## 4단계 — 분석 체크리스트

한 단계 끝낼 때마다 "무엇이 보였는지" 한 줄씩 기록해 둔다.

- [ ] **그래프 (M1)** — 전체 모양은? 오르막? 물결? 들쭉날쭉?
- [ ] **이상치 점검 (M2)** — 튀는 값이 있다면, 지우기 전에 원인부터.
- [ ] **이동평균 (M3)** — 창 크기는 무엇으로, 왜? (일별 데이터의
  7은 일주일이지만, 주별 데이터라면 7은 7주다.)
- [ ] **계절성 (M4)** — 월별·요일별 패턴이 있는가? **없다는 발견도
  발견이다.**

---

## 5단계 — 예측 대결

내 데이터에서 naive 예측과 이동평균 예측을 겨루게 한다(M5·M6).

```python
actual = df["값열"]
pred_naive = actual.shift(1)
pred_ma = actual.rolling(window=7).mean().shift(1)
```

- `.shift(1)`은 "예측은 전날까지의 정보만"이라는 규칙 —
  **정답 미리 보기 금지**(M5)가 코드 한 조각에 들어 있다.
- 마지막 구간을 시험 기간으로 떼어 놓고, 평균 오차(MAE)로
  승자를 가린다.
- 무승부거나 애매하면 시험 기간을 늘려 다시 재 본다.

---

## 발표 — 5분의 틀

그래프 한 장 = 발견 한 개. 다섯 장이면 충분하다.

1. **내 질문** — 한 문장.
2. **데이터 소개** — 출처, 기간, 행 수, 결측 처리.
3. **발견 셋** — 각각 그래프 한 장과 함께.
4. **예측 대결** — 두 MAE와 승자, 이유 한 문장.
5. **한계와 다음 질문** — 데이터가 더 있다면 뭘 보고 싶은가?

---

## 발표의 태도

- 잘 나온 결과만 보여줄 필요는 없다.
- 패턴이 안 나온 것도, 예측이 많이 틀린 것도, "이 데이터로는 판단
  불가"도 정직한 발견이다.
- 청중은 발표마다 질문을 하나씩 준비한다 — 예: "그 튀는 값은 무슨
  일이었나요?", "창 크기를 왜 그걸로 골랐나요?"

---

## 무엇을 보고 발표를 판단하나

발표에서 눈여겨보는 항목:

- 질문이 데이터로 답할 수 있게 분명한가.
- 데이터 출처·기간·행 수·결측을 제대로 설명했는가.
- 발견마다 그래프라는 근거가 있는가.
- 튀는 값의 원인을 찾아봤는가.
- 두 예측 방법을 MAE로 비교하고 승자의 이유를 말했는가.
- 이 프로젝트의 한계를 스스로 짚었는가.

---

## 이제 활동지로

1. 질문을 정하고, 데이터 후보를 고른다.
2. CSV를 Colab에 불러와 첫 점검(행 수·기간·결측)을 한다.
3. M1–M4 체크리스트로 분석하고, 발견을 세 줄로 기록한다.
4. naive와 이동평균을 겨루게 하고, 승자와 이유를 적는다.
5. 다섯 장짜리 발표를 준비한다.
