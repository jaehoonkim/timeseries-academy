# M8. 미니 프로젝트 — 강의자 노트

- 목표: 각자 고른 시계열 데이터로 질문 → 수집 → 분석 → 예측 → 발표를
  완주한다. 새 도구는 없다 — M1~M7의 총동원.
- 준비물: 학생당 Colab + **백업 데이터 2~3종**(아래 참고).
  팀은 1~2인 권장 (2인이면 역할: 코드 담당 + 기록·발표 담당 교대).
- 시간: **2회차 권장** — 1회차(75분) 킥오프 + 작업, 2회차(75분)
  마무리 작업 + 발표. 1회로 압축한다면 "질문·데이터 준비"(워크북
  1~2번)를 사전 숙제로 내야 한다.

## 사전 준비 (강의자)

- **백업 데이터**: 데이터 수집에서 막히는 팀이 반드시 나온다(경험상
  1/3). 즉시 건넬 수 있는 CSV를 2~3개 준비해 둘 것. 추천:
  1. 기상포털에서 받은 **다른 도시 기온** (서울과 비교 질문이 가능)
  2. 서울 **미세먼지** 일평균 (계절성 뚜렷, 사건도 있음)
  3. 이 저장소 CSV 그대로 + **일교차 질문** (practice의 예시
     프로젝트 — 파일 준비가 0초)
- practice.md의 예시 프로젝트(일교차)를 직접 완주해 둘 것 — 순회
  지도 중 모든 단계의 "막혔을 때 보여줄 예시"가 된다.
- 발표 순서 추첨 방법과 타이머를 정해 둔다.

## 수업 흐름 (1회차)

### 0:00–0:10 킥오프 — 도구 상자 회고

> 오늘은 새로 배우는 게 없어. 대신 지금까지 배운 걸 다 써.
> 그래프로 보고(M1), 요약하고 튀는 값을 의심하고(M2), 창을 밀어
> 흐름을 찾고(M3), 반복을 찾고(M4), 예측하고 오차로 재고(M5),
> 그걸 코드로(M6), 날짜 인덱스와 결측 처리까지(M7).
> 도구 상자는 꽉 찼어. 이제 **네 데이터**를 가져와.

워크북 1번(질문 정하기)을 10분 안에 끝내게 한다 — 여기서 오래
끌수록 분석 시간이 사라진다. 질문이 안 나오는 팀에는 데이터 후보
표에서 거꾸로 고르게 한다("걸음 수 → 그럼 질문은?").

### 0:10–0:30 데이터 준비 (워크북 2번)

가장 많이 막히는 구간. 순회하며 즉시 해결한다:

- **한글 깨짐** → `encoding="cp949"`. 공공데이터 최다 빈출.
- **날짜 파싱 실패** → 날짜 열이 "2026.08.17"이나 "20260817" 형태면
  `parse_dates`가 못 읽을 수 있다.
  `df.index = pd.to_datetime(df.index, format="%Y.%m.%d")`처럼
  형식을 지정한다 (format 문자열은 그 자리에서 같이 만들어 주면 된다).
- **엑셀 파일(.xlsx)** → `pd.read_excel("파일.xlsx")` 또는 엑셀에서
  CSV로 다시 저장.
- **기간 부족** → 질문을 데이터에 맞게 줄인다 ("연 패턴" → "요일
  패턴"). 두 번 반복 원칙(M4)을 기준으로 판정.
- 15분이 지나도 데이터가 없는 팀 → 주저 없이 **백업 데이터** 투입.
  데이터 수집이 아니라 분석·발표가 이 모듈의 본체다.

### 0:30–1:10 분석 + 예측 (워크북 3~4번)

순회 지도 포인트:

- 각 팀의 그래프를 보고 **"튀는 값 있네 — 무슨 일이 있었어?"** 를
  물어 주면 M2의 문화(지우기 전에 원인)가 살아난다.
- **주별 데이터** 팀: `rolling(window=7)`이 7주라는 것을 꼭 짚어 줄 것 —
  창 단위는 "행"이지 "일"이 아니다.
- 요일 패턴이 안 나온 팀이 실망하면: 기온도 그랬다(M4) — 없다는
  발견도 발표 재료가 된다.
- 예측 대결이 무승부인 팀: 시험 기간을 늘리게 한다 (M5의 기간
  확장). 그래도 비슷하면 그 자체가 발견이다.

### 1:10–1:15 1회차 마무리

발표 틀(워크북 5번)을 소개하고, 다음 시간까지 그래프 다섯 장을
준비해 오게 한다. "그래프 한 장 = 발견 한 개"만 반복 강조.

## 수업 흐름 (2회차)

- 0:00–0:20 마무리 작업 + 발표 리허설 (팀 내에서 1회).
- 0:20–1:05 발표 — 팀당 5분 + 질문 2분. **청중 규칙**: 발표마다
  질문 하나씩 준비한다. 좋은 질문의 예를 미리 준다: "그 튀는 값은
  무슨 일이었나요?"(M2), "창 크기를 왜 그걸로 골랐나요?"(M3),
  "naive는 이겨 봤나요?"(M5).
- 1:05–1:15 수료식 — 워크북 6번 "나의 세 문장"을 몇 명 발표.

> 여덟 번 동안 한 걸 한 문장으로 하면: **시간이 담긴 데이터를 보고,
> 요약하고, 흐름과 반복을 찾아, 내일을 짐작하고, 얼마나 틀렸는지
> 쟀다.** 이게 시계열 분석의 전부이고, 나머지는 더 좋은 도구일 뿐이야.

## 평가 루브릭 (발표)

| 항목 | 잘함 | 보통 | 아쉬움 |
|---|---|---|---|
| 질문 | 한 문장, 데이터로 답 가능 | 질문은 있으나 모호 | 질문 없이 데이터만 |
| 데이터 기술 | 출처·기간·행 수·결측 모두 언급 | 일부 언급 | 언급 없음 |
| 발견 | 그래프를 근거로 3가지 | 그래프 있으나 해석 약함 | 그래프 나열뿐 |
| 이상치 | 원인을 조사/추측해 설명 | 있다고만 언급 | 못 봄 / 말없이 삭제 |
| 예측 | 두 방법 MAE 비교 + 승자 이유 | MAE 하나만 제시 | 예측 없음 |
| 한계 | 스스로 한계와 다음 질문 제시 | 물으면 답함 | 인식 없음 |

점수화보다는 피드백 언어로 쓰는 것을 권장 — "이상치 원인까지 물었네,
M2를 제대로 썼다"처럼 모듈 이름으로 칭찬하면 배운 것이 연결된다.

## 예상 질문 / 오개념

- **"계절성이 안 나와요"** — 없음도 발견(M4의 요일 실험). 단, 기간이
  주기의 2배가 안 되는 건 아닌지 먼저 확인 — 그 경우 "이 데이터로는
  판단 불가"가 정직한 결론이다.
- **"예측이 너무 안 맞아요"** — 오차의 크기는 방법만이 아니라
  데이터의 성질(M5 겨울 대결). 검색량·미세먼지처럼 출렁이는 데이터는
  기온보다 오차가 클 수밖에 없다. naive 대비 나아졌는지만 보면 된다.
- **"결측이 너무 많아요"** — 왜 비었는지부터(M7). 주말마다 비는
  데이터(주식 등)는 결측이 아니라 "원래 없는 날"이다 — 있는 날만으로
  분석하면 된다.
- **"값이 문자로 읽혀요 (예: '1,234')"** — 천 단위 쉼표.
  `pd.read_csv(..., thousands=",")` 옵션으로 해결.
- 오개념 주의: **"발표는 잘된 것만 보여줘야 한다"** — 안 나온 패턴,
  큰 오차, 판단 불가도 정직하게 말하는 것이 이 과정의 태도다.
  루브릭의 "한계" 항목이 그 자리다.

## 강의자용 심화 — 이 다음은?

과정을 더 이어가고 싶은 학생을 위한 지도:

- **자기상관(ACF)**: "어제와 오늘이 얼마나 닮았나"를 모든 간격에
  대해 재는 도구 — M1 심화에서 언급한 개념의 정식 버전. naive가
  강했던 이유를 숫자로 설명해 준다.
- **시계열 분해(STL)**: M3(추세)+M4(계절성)를 자동으로 분리해 주는
  `statsmodels`의 도구 — 우리가 손으로 한 것의 자동화.
- **지수평활·ARIMA**: naive와 이동평균의 정식 후속 모델들. 대부분의
  입문서가 여기서 시작하는데, 이 과정을 마친 학생은 "naive를 이기는
  게 목표"라는 관점을 이미 갖고 있다.
- 데이터 대회(데이콘·캐글)의 시계열 과제는 이 파이프라인 그대로에
  모델만 좋아진 것 — 고등학생쯤 도전해 볼 만하다.
