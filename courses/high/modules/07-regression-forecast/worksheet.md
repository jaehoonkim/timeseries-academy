## 3. 특징 테이블 — 회귀는 표로 배운다

회귀에게 재료를 줄 때는 표로 준다. 각 날짜마다 "재료들"과
"정답(그날 기온)"을 한 줄에 놓은 표다 — 예측에 쓰는 재료 열을
**특징**(feature)이라 부른다. 첫 특징은 하나, 어제 기온이다 —
읽는 법:

> `pd.DataFrame({"어제": t.shift(1), "오늘": t})`
> = "어제" 열과 "오늘" 열을 나란히 놓은 표를 만들어라
> — shift(1)은 H5·H6의 그 도구: 오늘 자리에 어제 값
>
> `.dropna()`
> = NaN이 든 줄을 버려라(drop) — 첫날은 어제가 없으므로

```python
data = pd.DataFrame({"어제": t.shift(1), "오늘": t}).dropna()
train = data[:"2025-07-31"]
test = data["2025-08-01":]
len(train), len(test)
```

분할선은 H6과 같다 — 앞 2년으로 배우고, 마지막 1년으로 채점한다.

## 4. 첫 회귀 선수 — 어제 하나로

직선 찾기를 시켜 보자. 도구는 Colab에 기본으로 있는
scikit-learn, 직선으로 하는 회귀라서 이름이 LinearRegression
(선형회귀)이다 — 읽는 법:

> `model1 = LinearRegression()`
> = 새 회귀 모형을 하나 준비하라
>
> `model1.fit(train[["어제"]], train["오늘"])`
> = 훈련 구간의 (재료, 정답)으로 **배워라**(fit) — 오차 제곱
> 합이 가장 작은 직선을 찾는다
>
> (대괄호가 두 겹인 `[["어제"]]`는 "이 목록의 열들만 골라 표
> 모양을 유지하라"다 — 회귀는 재료를 언제나 표로 받는다)

```python
from sklearn.linear_model import LinearRegression

model1 = LinearRegression()
model1.fit(train[["어제"]], train["오늘"])
model1.coef_, model1.intercept_
```

배우고 나면 찾은 직선을 보여 준다: `coef_`가 재료마다의 **기울기
곧 계수**(coefficient), `intercept_`가 절편이다. (이름 끝의
밑줄은 "학습이 끝난 뒤에 생긴 값"이라는 scikit-learn의 표기
버릇이다.)

계수가 `array([...])`처럼 대괄호에 싸여 나오는 건 고장이 아니다
— 재료를 표로 받았으니 계수도 **재료마다 하나씩, 목록으로**
돌려준다. 지금은 재료가 하나라 한 칸짜리 목록이고, 5절에서
재료가 둘이 되면 두 칸이 된다.

그런데 왜 성적보다 이 두 숫자를 먼저 보나? 성적은 모형이
**얼마나** 잘하는지만 말해 주고, 기울기와 절편은 **어떻게**
예측하는지를 말해 준다. 읽는 방법은 1절에서 이미 두 번 해 봤다:

- **기울기** = 재료를 얼마나 믿나 — 어제가 1도 오르면 예측이
  몇 도 오르나. 1이면 어제를 그대로 믿는 것(naive), 0.5면
  절반만 믿는 것(신중 직선).
- **절편** = 재료와 무관하게 깔아 두는 밑값 — 직선에 심어 놓은
  고정 정보다. 신중 직선은 절편 6.4에 연평균의 절반이 심겨
  있어 겨울마다 참패했다(Q2).

두 숫자를 읽으면 이 모형이 어떤 전략의 선수인지 **채점하기 전에
미리** 보인다 — Q4가 바로 그 읽기다.

**Q4.** 찾아낸 기울기와 절편은 얼마인가? 그 기울기, 어디서 많이
본 숫자 아닌가(H5)? 그리고 이 직선은 1절의 두 직선 중 누구와
거의 같은가?

기울기: ______  절편: ______  본 곳: ____________

닮은 직선: ____________

이름의 유래를 여기서 만난다: 19세기 갈턴(Galton)은 아버지와
아들의 키에서 "극단은 평균 쪽으로 **되돌아온다**(regress)"를
발견했고, 그 직선의 이름이 회귀가 되었다. 우리 직선의 기울기도
1보다 살짝 작은 0.98 — 어제가 극단일수록 예측을 평균 쪽으로
아주 조금 당긴다.

이제 시험을 치르게 하자 — 읽는 법:

> `model1.predict(test[["어제"]])`
> = 시험 구간의 재료로 **답안을 써라**(predict)
>
> `pd.Series(..., index=test.index)`
> = predict는 날짜 없는 숫자 뭉치로 돌려주므로, 시험 구간의
> 날짜를 도로 입힌다 — 그래야 실제 기온과 짝지어 채점할 수 있다

```python
pred1 = pd.Series(model1.predict(test[["어제"]]), index=test.index)
e1 = test["오늘"] - pred1
e1.abs().mean(), (e1**2).mean() ** 0.5
```

naive의 성적도 같은 표에서 바로 나온다 — "어제" 열이 곧 naive의
예측이므로:

```python
e_naive = test["오늘"] - test["어제"]
e_naive.abs().mean(), (e_naive**2).mean() ** 0.5
```

## 5. 재료를 늘린다 — 달의 보통

Q5의 무승부를 풀어 보자. 1/20 줄에서 모형에게 준 재료는 어제
기온 -4.7, 숫자 하나뿐이다. naive는 그 숫자를 그대로 예측으로
내니, 이 한 칸의 예측력을 이미 다 쓰고 있는 셈이다. 회귀가 한
일은 같은 숫자에 기울기와 절편을 입힌 것뿐인데, 최선의 옷이
y ≈ x였다(Q4). **같은 재료로는 같은 답이 나온다.**

이기려면 어제 칸에 **없는** 정보 — 새 재료가 필요하다. H4에서
만든 "그 달의 보통"(월별 프로필)을 데려오자 — 단, H6의 규칙대로
**프로필도 훈련 구간에서만** 계산한다(시험 구간을 미리 보면
반칙이다). H4의 groupby 그 계산이다:

```python
train_t = t[:"2025-07-31"]
profile = train_t.groupby(train_t.index.month).mean()
profile.round(1)
```

표가 12줄로 꽉 찬 게 이상해 보일 수 있다 — 7월 31일에서
잘랐는데 왜 8월부터 12월도 있을까? **시작이 2023년 8월**이기
때문이다. 7/31은 끝점일 뿐, 훈련 2년에는 열두 달이 모두 두
번씩 들어 있다. 검산: 달마다 약 60일, 열두 달을 합치면 Q3의
훈련 730일과 맞아떨어진다.

**Q6.** 1월과 8월의 보통은 몇 도인가? H4에서 본 프로필과 숫자가
조금 다르다 — 왜 다를까?

1월: ______ °C  8월: ______ °C  다른 이유: ____________

프로필은 12줄짜리 표다. 이걸 1,096일 각각에 입히는 도구가 map이다
— 읽는 법:

> `month = pd.Series(t.index.month, index=t.index)`
> = 각 날짜에 그 날짜의 월 번호(1~12)를 적은 시리즈
>
> `month.map(profile)`
> = 월 번호를 이름표 삼아 profile 표에서 값을 **찾아와라**(map)
> — 8월 10일 줄에는 8월의 보통이 온다. H4의 transform과 같은
> 일을, "훈련에서 배운 표"로 하는 방법이다

```python
month = pd.Series(t.index.month, index=t.index)
data2 = pd.DataFrame({"어제": t.shift(1),
                      "달의보통": month.map(profile),
                      "오늘": t}).dropna()
train2 = data2[:"2025-07-31"]
test2 = data2["2025-08-01":]
```

재료 두 개로 다시 배운다:

```python
model2 = LinearRegression()
model2.fit(train2[["어제", "달의보통"]], train2["오늘"])
model2.coef_, model2.intercept_
```

계수 목록이 4절의 예고대로 두 칸이 됐다. 어느 칸이 어느 재료의
계수인가 — 출력에 이름표는 없지만, **fit에 준 열 순서 그대로**다:
첫 칸이 어제, 둘째 칸이 달의 보통.
