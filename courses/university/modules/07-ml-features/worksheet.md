## 1. 특징 — 시계열을 표로 바꾸는 발상

고전 가족은 시계열을 시계열인 채로 다뤘다. ML의 발상은 다르다:
**각 날짜를 표의 한 줄로** 만든다 — 그날을 예측하는 데 쓸
재료들을 열로 늘어놓고, 그날의 실제 값을 정답으로 둔다. 이 재료
열 하나하나를 **특징**(feature)이라 부른다.

재료는 세 갈래에서 온다 — 전부 구면이다:

- **과거의 값** — 어제, 지난주 같은 요일. U1에서 naive를 만들던
  `shift`가 바로 이 일을 한다(shift(1) = 오늘 자리에 어제 값).
- **달력** — 요일, 월. U1 Q8에서 요일 프로필을 만들던
  `index.dayofweek`(월요일이 0)가 그대로 열이 된다.
- **최근의 평균** — U2의 `rolling` 평균.

기온의 표부터 만들자 — 읽는 법:

> `pd.DataFrame({"이름": 열, …}, index=t.index)`
> = 열들을 묶어 표로 — 이름표(날짜)는 t의 것을 쓴다
>
> `t.rolling(7).mean().shift(1)`
> = 최근 7일 평균을 **하루 밀어서** — 밀지 않으면 오늘의
> 평균에 **오늘 값**이 들어 있다

```python
X = pd.DataFrame({"어제": t.shift(1), "그제": t.shift(2),
                  "지난주": t.shift(7),
                  "최근7일평균": t.rolling(7).mean().shift(1),
                  "월": t.index.month}, index=t.index).dropna()
y = t[X.index]
X.head(3)
```

dropna로 첫 7일이 사라졌다(1,096일 → 1,089일) — 지난주가 없는
날들이다, U6 잔차의 첫 7일과 같은 이유. `y = t[X.index]`는 표에
남은 날짜들의 정답만 골라 둔 것이다.

## 2. 도전자 — 부스팅 나무, 그리고 기온 대결

도전자의 정식 이름은 **그래디언트 부스팅**(gradient boosting) —
실무에서는 부스팅 트리, GBDT라고도 부른다(검색할 때는 이
이름들로). 작은 **결정 트리**(decision tree, 의사결정나무) —
"어제가 20도보다 높은가?" 같은 갈래 질문 몇 개짜리 — 수백
그루를 차례로 심되, 새 나무마다 **앞 나무들이 남긴 오차를
깎도록** 심는 방법이다. 이 과정에서는 우리말로 **부스팅
나무**라 부르자. 안의 수학은 오늘 필요 없다(심화 참고) —
우리는 쓰는 법과 채점만 안다.

도전자를 이 모형으로 고른 것은 과정의 취향이 아니다 — 표로 된
데이터에서 부스팅 계열(XGBoost·LightGBM 등)은 지난 10년 실무와
대회의 **표준**이고, 시계열 대회에서도 특징 표 + 부스팅이 우승
공식이다. 오늘 쓰는 것은 그 계열의 scikit-learn판이다. 읽는 법:

> `HistGradientBoostingRegressor(random_state=0)`
> = 부스팅 나무 모형 (random_state=0은 결과 고정용 —
> 안 적으면 실행마다 끝자리가 흔들릴 수 있다)
>
> `.fit(재료 표, 정답)` / `.predict(재료 표)`
> = 배워라 / 답안을 써라 — 재료와 정답을 **따로** 주는 것이
> statsmodels와 다른 점이다

분할은 늘 쓰던 그 날짜다. predict가 돌려주는 것은 날짜 이름표가
없는 값 묶음이라, `pd.Series(…, index=…)`로 이름표를 다시
붙인다(그래야 실제와 날짜끼리 뺄 수 있다):

```python
from sklearn.ensemble import HistGradientBoostingRegressor

X_train, X_test = X[:"2025-07-31"], X["2025-08-01":]
y_train, y_test = y[:"2025-07-31"], y["2025-08-01":]

ml = HistGradientBoostingRegressor(random_state=0).fit(X_train, y_train)
pred = pd.Series(ml.predict(X_test), index=X_test.index)
e = y_test - pred
round(e.abs().mean(), 2), round((e**2).mean() ** 0.5, 2)
```

## 4. 심판을 여러 번 — rolling-origin 교차검증

방금 우리는 특징 두 벌(X1, X2)을 **시험 성적으로** 비교했다.
수업이니까 결과부터 봤지만, 실전에서 이렇게 특징을 고르면
시험지가 훈련지가 되는 반칙이다. 고전에는 훈련 안의 심판
AIC(U5)가 있었는데, ML에는 AIC가 없다.

ML의 심판은 더 직접적이다: **훈련 구간 안에서 가짜 시험을
치른다.** 훈련의 앞부분으로 배우고 그다음 토막을 맞혀 채점한다
— 한 번이면 우연일 수 있으니, 배우는 구간의 끝(origin)을 뒤로
밀어 가며 **여러 번** 반복한다. 그래서 이름이
**rolling-origin 교차검증**(cross-validation)이다. 시험지는
끝까지 열지 않는다. 읽는 법:

> `TimeSeriesSplit(n_splits=5).split(X1_train)`
> = 훈련 구간을 시간 순서대로 다섯 번의 (배움, 가짜 시험) 짝으로
> 잘라, 각 짝의 **행 번호 목록**을 내놓아라 — 무작위로 섞지
> 않는 것이 핵심이다(시간 순서가 곧 반칙 방지)
>
> `X1_train.iloc[tr]`
> = 행 번호 목록으로 그 행들을 꺼내라

```python
from sklearn.model_selection import TimeSeriesSplit

maes = []
for tr, va in TimeSeriesSplit(n_splits=5).split(X1_train):
    m = HistGradientBoostingRegressor(random_state=0).fit(X1_train.iloc[tr], y1_train.iloc[tr])
    maes.append(abs(y1_train.iloc[va] - m.predict(X1_train.iloc[va])).mean())
round(sum(maes) / 5 / 1e4, 1)
```

같은 심판을 빨간날 표에도:

```python
maes = []

    maes.append(abs(y2_train.iloc[va] - m.predict(X2_train.iloc[va])).mean())
```
